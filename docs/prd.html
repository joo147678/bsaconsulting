PRD — Minutes studio (UI/UX)

Product: نظام محاضر الجمعيات العمومية · Internal · Arabic only

Problem

BSA accountants produce ordinary and extraordinary general assembly minutes for 100+ clients in Word. Each cycle costs time: re-typing company data, formatting A4, sending a file, waiting for comments, iterating. The client we are pitching must see, in one demo, that this operation can be drafted once, reviewed once, and issued from the tool.

Users

Role Job in this product v1 (now)
Accountant Select company, draft محضر, send for review, print Primary click-path in the UI
Supervisor Open review link, read A4, approve Second click-path; no real login
Client company Receives the finished minute — does not use the tool Out of product; in the sales story only

Goal and success

Goal: a clickable Arabic UI that sells the time-saved / fewer-iterations story.
Success: BSA issues next month’s client minutes from this tool, not Word. Closing that proof supports a larger BSA deal.

In scope now (UI/UX only)

  • Workbench already built: companies, two minute types, live A4, completeness, print.
  • Status model on screen: مسودة → قيد المراجعة → معتمد.
  • Accountant action: “Send for review” (simulates WhatsApp: show that a supervisor would get a link).
  • Supervisor view: open the same minute via a review URL; first open sets status to in review; primary action is Approve.
  • Arabic copy only. Current visual layout is acceptable for v1.
  • Document content must read as Companies Law + BSA house style; do not invent a new legal form in this pass.

Explicitly out of this pass

  • Real WhatsApp API, SMS, or email delivery.
  • Accounts, permissions, cloud database, multi-device sync.
  • GAFI / tax / commercial-register filing.
  • English UI or bilingual PDF.
  • Client-facing portal.

Flow, next scope, risks

Target click-path (simulate, do not wire)

  1. Accountant opens a company and creates ordinary or extraordinary minutes.
  2. Fills the form against the live A4 until completeness is honest.
  3. Clicks send-for-review. UI confirms: supervisor will be notified on WhatsApp with a link. Status stays مسودة until the link is opened.
  4. Demo uses a “Open as supervisor” link (same machine). Opening it sets قيد المراجعة.
  5. Supervisor reads the paper, clicks اعتماد. Status becomes معتمد. Accountant can print / PDF.

Persistence may stay in the browser for this pass. The review URL can be a route such as /reports/:id?view=supervisor — enough for a live demo, not a production security model.

Next scope (do not start until this demo lands)

Item Why it waits
Roles + cloud Real accountant vs supervisor identities and shared files
WhatsApp notify Needs a hosted review link and a sender number
Audit trail Who opened, who approved, when — after the deal, not before

Risks

  • Legal template: house style is “good enough” for v1 only if a BSA supervisor signs off that the Arabic clauses are issuable.
  • Demo cheat: if send-for-review does nothing visible, the client will not believe the iteration story. The status change must be obvious.
  • 100-client scale is a next-scope problem. This pass must look like it can hold that book, not actually host it.

Build order after this PRD

  1. Add send-for-review + supervisor view + status transitions in the existing UI.
  2. Walk the demo: draft → WhatsApp story → in review → approved → print.
  3. Stop. Cloud, roles, and WhatsApp API are a separate project.
